# Milestone 3 – UI Optimization: Topic Forest

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/UxAzhangxiaohua/hci_m3/blob/main/ui_optimization.ipynb)

When a student asks the AI a new question, our prototype decides where the question goes in the student's knowledge tree. It can add it to an existing topic, open a new topic, or also move related older questions into the new topic. We solve this decision as an integer program with Gurobi, once per question, over a scripted study session.

## Files

## Where the proposals and scores come from

One LLM prompt, `judge_prompt.txt` (built by `judge_prompt.batch_prompt`), does two tasks in order:

1. **Propose**: for each new question, in the order asked, suggest at most one new topic (name and parent) if no existing topic fits it well.
2. **Judge**: rate every question against every topic, the starting ones and all proposals, from 1 to 5.

We sent it once to Claude Sonnet 5.5 and stored the JSON answer unchanged as `judge_scores.json`; the model and date are declared in the notebook (`JUDGE_SOURCE`, Section 2). In the prototype the same parts are sent through the LLM API for every new question (`judge_prompt.step_prompt`).

If the session changes:

```bash
python judge_prompt.py > judge_prompt.txt     # regenerate the prompt
# send judge_prompt.txt to the model, save its JSON answer as judge_scores.json,
# update JUDGE_SOURCE in the notebook, re-run the notebook
```

Without `judge_scores.json` the notebook still runs, using proposals and scores written by the authors (`AUTHOR_PROPOSALS`, `AUTHOR_SCORES` in `session.py`), and says so.

## The pipeline

1. **Session** (`session.py`): questions arrive one by one.
2. **Proposals and scores** (`judge_scores.json`): the LLM's proposed topics and its rating of every question against every topic (1–5), rescaled to a fit between 0 and 1. A proposal that is not created stays open for later questions.
3. **Optimization** (notebook, Section 4–5): for each new question, Gurobi picks the placement that maximizes

   *fit − cost of new topics − penalty for topics that are too full or too sparse − cost of moving old questions*

   The result becomes the tree for the next question.
4. **Visualization** (Section 6): the tree after every step, a step in detail, and animations.
5. **Comparison** (Section 7): the same session with two simple rules (always use an existing topic; always take the best proposal).
6. **What-if** (Section 8): re-run the session with different weights and see where the decisions change.
